## 1. YOLO 是什么

**YOLO = You Only Look Once**（你只看一次）。

计算机视觉里有两大任务经常被混淆：

- **分类（classification）**：这张图里是什么？→ 输出一个类别，如"睁眼"
- **检测（detection）**：这张图里有什么、分别在哪？→ 输出若干个**边界框
  （bounding box，简称 bbox）**，每个框带类别和置信度（confidence，模型对
  自己判断的确信程度，0~1）

YOLO 做的是检测。它的核心思想只有一句话：**把"先找候选区域再逐个分类"的两步
（两阶段，如 R-CNN 系列）合成一步——用单个神经网络对整张图做一次前向传播，
直接吐出所有框**。这就是"只看一次"的含义，也是它快的根本原因。

本项目的场景里"检测"体现在哪？看 `configs/mrl_eye.yaml`：

```yaml
nc: 2          # number of classes：2 类
names:
  0: open_eye     # 类别 0：睁眼
  1: closed_eye   # 类别 1：闭眼
```

再看一张标签文件 `datasets/mrl_eye_yolo/labels/train/s0001_00001_0_0_0_0_0_01.txt`：

```
0 0.5 0.5 1.0 1.0
```

这行就是 YOLO 的标注格式：**类别 中心x 中心y 宽 高**（后四个数都按图宽高归一化
到 0~1）。`0.5 0.5 1.0 1.0` 意思是"框住整张图"——因为 MRL 数据集每张图本身就是
一个眼部特写，眼睛几乎充满画面，所以框就是全图。模型真正学到的是：
**这种画面对应类别 0（睁眼）还是类别 1（闭眼）**。
（为什么不自己画小框？因为定位眼睛这件事我们已经交给 MediaPipe 了，
见 README 第八节"集成"。）

## 2. YOLO 的结构

现代 YOLO（v8 之后的 Ultralytics 系列，含 YOLO26）都是 **anchor-free** 的三段式：

```
输入图像 (如 128×128)
   │
   ▼
┌─────────────┐
│  Backbone    │  主干网络：一层层卷积，把像素变成"特征"
│  (提特征)    │  浅层特征=边缘/纹理，深层特征=语义（"这是一只眼睛"）
└──────┬──────┘
       ▼
┌─────────────┐
│  Neck        │  颈部：把深浅特征融合（FPN + PAN 结构），
│  (融合特征)  │  让"看清小细节"和"看懂大意"两条信息流汇合
└──────┬──────┘
       ▼
┌─────────────┐
│  Head        │  检测头：在特征图的每个位置上直接预测——
│  (出预测)    │  这里有一个目标吗？什么类？框在哪？多确信？
└─────────────┘
```

几个关键机制，用大白话解释：

- **多尺度检测**：Neck 会输出三种分辨率的特征图（习惯叫 P3/P4/P5）。小目标在
  高分辨率层上检测（像素还够用），大目标在低分辨率层上检测（语义够强）。我们的
  眼睛特写目标很大，主要走低分辨率路径，所以 `imgsz=128` 也够用。
- **anchor-free**：老版 YOLO 要先在图上铺几百个预设框（anchor），网络预测"相对
  预设框的偏移"。anchor-free 版本直接回归框的 **(中心x, 中心y, 宽, 高)**，更简单
  也更好训——标签格式（上面那 5 个数）就是按这个设计的。
- **NMS（非极大值抑制）**：传统检测器对同一个目标会吐出好几个重叠的框，需要
  NMS 把重叠的留一个。**YOLO26 是 end-to-end 无 NMS 设计**：网络自己解决重复框，
  部署时后处理更少、速度更稳定（对要放到轮椅上的边缘设备是实打实的好处）。

## 3. YOLO26 特别在哪

YOLO26 是 Ultralytics 2025 年 9 月发布的版本（本项目用 `ultralytics 8.4.164`）。
相对 v8/v11 的关键点，按对本项目的影响排序：

1. **端到端、无 NMS**：上面说过，推理管线更简单，适合部署。
2. **家族五档**：`n / s / m / l / x`（nano → extra），参数量和精度递增。我们选
   **yolo26n**——训练完的 best.pt 只有约 6MB、**237 万参数、5.3 GFLOPs**，
   GPU 上单张 1.43ms。轮椅场景要实时 + 省电，nano 档是合理起点；
   以后嫌不够准再升 s 档，代码一行不用改（换个权重名）。
3. **多任务一套 API**：detect / segment / classify / pose / obb 全支持，训练和
   推理接口一致——这就是为什么本项目所有脚本里都是同一句
   `YOLO("yolo26n.pt")` → `.train()` / `.predict()` / `.val()`。
4. **边缘部署友好**：官方主推导出到 LiteRT 等端侧运行时（`yolo export format=...`），
   将来若把推理挪到低功耗设备，这条路是现成的。

## 4. 训练是怎么回事

对照本项目：`scripts/train_eye.py` → 训练日志 → `runs/eye_yolo26n/`。
训练一个检测模型 = 让网络在"预测"和"标签"之间不断算差距（损失），再用梯度
下降把差距调小。下面按时间顺序拆解每个概念。

### 4.1 迁移学习（transfer learning）

我们没有从随机权重开始训，而是加载 `yolo26n.pt`——官方在 **COCO 数据集**
（33 万张图、80 类日常物体）上预训练过的权重。网络已经"会看"了（懂边缘、纹理、
部件），我们只需要教它"睁眼/闭眼"这个新区分。这就是为什么 84,898 张小图
**9.2 分钟**就训完——绝大部分知识是白捡的。你以后训任何模型，除非数据量极大
且领域极特殊，都应该从预训练权重出发。

### 4.2 数据划分与"数据泄漏"

`scripts/prepare_mrl_dataset.py` 做的事：解压 → 从文件名解析标签 → **按受试者**
划分。重点讲为什么按"人"划分而不是随机按"图"划分：

- MRL 里每个受试者有几千张图，长相、眼型、拍摄角度几乎一样。
- 如果随机划分，同一个人的图会同时出现在训练集和验证集——模型只要"背下"这个
  人的样子就能得高分，**验证指标虚高，实际换个人就拉胯**。这叫**数据泄漏
  （data leakage）**。
- 我们把 s0010/s0020/s0030 整人划进验证集，等于考试用的"陌生人"，测出来才是
  真实泛化能力。README 里"跨受试者"四个字就是这个意思。

### 4.3 超参数：imgsz、batch、epoch

| 超参数 | 本项目取值 | 含义 |
|---|---|---|
| `imgsz` | 128 | 训练/推理时把图缩放到 128×128。源图才 83×83，放大太多没信息可加，反而慢 |
| `batch` | -1（自动） | 一批喂几张。batch 越大梯度越稳、GPU 利用率越高，但显存吃得多；-1 让 ultralytics 按显存自动试 |
| `epochs` | 50（上限） | 全部训练数据过一遍 = 1 epoch。我们设上限 50，实际没跑满（见早停） |
| `patience` | 10 | 早停耐心值：连续 10 轮验证指标没提升就停 |

### 4.4 数据增强（augmentation）

训练时 ultralytics 默认对每张图做随机变换，等于"免费扩充"了数据、逼模型学本质
特征而不是死记背景。本项目实际生效的（见 `runs/eye_yolo26n/args.yaml`）：

- `mosaic=1.0`：把 4 张图拼 1 张，逼模型在复杂布局里找目标（最后 10 轮自动关掉，`close_mosaic=10`）
- `fliplr=0.5`：50% 概率水平翻转
- `hsv_h=0.015, hsv_s=0.7, hsv_v=0.4`：色调/饱和度/亮度随机抖动（模拟不同光照）
- `scale=0.5, translate=0.1`：随机缩放、平移

注意：对"睁/闭眼"这个任务，翻转和亮度抖动都合理；如果是"左右方向"类任务，
水平翻转就会把左翻成右，需要关掉——**增强要跟着任务语义走**。

### 4.5 损失函数：results.csv 里那三列到底是什么

打开 `docs/training/results.csv`，训练部分有三列损失：

| 列名 | 是什么 | 大白话 |
|---|---|---|
| `box_loss` | IoU 系框回归损失 | "你画的框和真值框重叠得够不够好" |
| `cls_loss` | 分类损失（交叉熵系） | "你说是睁眼，到底是不是睁眼" |
| `l1_loss` | 框坐标的 L1 损失 | "框的坐标数值上差多远"（逐像素级惩罚，帮框收敛得更正） |

三项按权重加总（本项目 `box=7.5, cls=0.5`），权重反映"定位比分类更重要"的先验。
训练的本质就是：**每个 batch 算一次这三项 → 反向传播算梯度 → 优化器改一遍权重
→ 循环**。训练集损失（train/）持续下降说明"学会了"；验证集损失（val/）跟着降
说明"真会了"，val 反弹说明开始"背题"（过拟合）。

### 4.6 学习率与 warmup（你曲线里尖峰的来源）

学习率（lr）= 每次改权重的步子大小。本项目默认策略：前 3 轮 warmup（从很小的
lr 慢慢加到 0.01，防止开局步子太大把预训练知识踩坏），之后按余弦/线性策略衰减。
`docs/training/curves_loss.png` 里 val 分类损失在第 5、13、16 轮的尖峰，就是
warmup 结束后 lr 较大 + 验证集只有 3 个人（2,487 张）造成的正常波动——个别难
 subject 的图会阶段性把 val loss 顶起来。**判断模型好坏看 mAP 曲线，别被 val loss
 的锯齿吓到**。

### 4.7 早停（early stopping）

`patience=10` 的含义：以 mAP50-95 为准，连续 10 轮没创新高就停。本项目第 13 轮
达到最高 mAP50-95=0.9401，第 22 轮触发早停。**best.pt 保存的是第 13 轮的权重**，
不是最后一轮——这就是"训练曲线在涨 ≠ 该用最后一轮"的常见误区。

## 5. 评估指标怎么读

### 5.1 IoU（交并比）

预测框和真值框的**交集面积 ÷ 并集面积**，1.0 完全重合。它是"框画得准不准"的尺子，
也是 mAP@0.5 里那个 0.5 的含义：IoU≥0.5 才算检出成功。

### 5.2 混淆矩阵 → precision / recall

你的混淆矩阵（`docs/comparison/confusion_matrix.png`，验证集 2,485 张有效帧）：

```
                    预测: 闭眼     预测: 睁眼
真值: 闭眼            1728           71        ← 闭眼共 1800
真值: 睁眼              70          616        ← 睁眼共 687（+2 张未检出）
```

四个格子各有名字（以"闭眼"为"正类"）：**TP=1728**（判对）、**FN=71**（漏报，
明明闭了说睁）、**FP=70**（误报，明明睁着说闭）、**TN=616**。

- **precision（精确率）** = TP/(TP+FP) = 1728/1798 = **96.1%**
  → "模型说闭眼的时候，真闭眼的概率"。误报代价高的场景看它（比如"闭眼=急停"
  的误触发）。
- **recall（召回率）** = TP/(TP+FN) = 1728/1800 = **96.0%**
  → "真闭眼的帧里，多少被抓住了"。漏报代价高的场景看它（漏掉一次眨眼确认）。
- 睁眼侧同理：precision = 616/(616+71) ≈ 89.7%，recall = 616/687 ≈ 89.7%。

睁眼比闭眼低约 6 个百分点，主要来自 MRL 文件名标签本身的噪声（文献报告标签
一致率约 90~97%——一些"睁眼"图其实是眯眼），所以 **94.33% 的总准确率是下限**。

### 5.3 mAP（mean Average Precision）

一句话：**PR 曲线下的面积，再对类别取平均**。

- 模型每个预测都带置信度。把置信度阈值从高到低扫一遍，每个阈值都能算出一对
  (precision, recall)，连成 PR 曲线。曲线越靠右上角越好。
- **mAP@0.5**：IoU 门槛 0.5 时算出的 AP，对"框画得准不准"要求宽松。
- **mAP@0.5:0.95**：IoU 门槛从 0.5 到 0.95 每 0.05 档各算一次再平均，对定位精度
  要求苛刻，是最常用的综合指标。本项目 0.9399，非常高（因为目标是"占满全图的
  大目标"，定位天然容易）。
- **准确率 ≠ mAP**：准确率只看"置信度最高那个预测的类别对不对"（我们取 0.5 阈值），
  是部署视角的数字；mAP 是"全阈值综合能力"，是论文视角的数字。两个都报，
  互为补充。

## 6. 本项目完整流程串讲

把 `scripts/` 的编号连起来就是一次完整的检测项目：

```
① verify_gpu.py          环境：torch 2.11.0+cu128 认得 RTX 5060 Ti（sm_120）
② prepare_mrl_dataset.py 数据：zip → 84,898 张 → 按人划分 → YOLO 目录树 + data.yaml
③ smoke_test_yolo26.py   冒烟：GPU 推理 16ms + COCO8 上 1 epoch 跑通训练循环
④ train_eye.py           训练：yolo26n + 84,898 张 → 早停 @22，best.pt @13，9.2 分钟
⑤ plot_training.py       可视化：results.csv → 损失曲线 + 指标曲线（matplotlib）
⑥ eval_eye_accuracy.py   评估：准确率 94.33% + 混淆矩阵 + MediaPipe 探测（0/300）
```

以后做模型 B（注视方向）就是同一套流程换个数据集：手机视频 → MediaPipe 自动
打标 → YOLO 格式 → ④⑤⑥ 原样重跑。

## 7. 常见坑 / 词汇表 / 参考资料

### 7.1 新手常见坑

| 坑 | 本项目的防法 |
|---|---|
| 数据泄漏（同人同图跨集） | 按受试者划分 |
| 只看训练损失自嗨 | val 指标 + 早停 + best.pt 取峰值轮 |
| 被验证损失锯齿吓到 | 小验证集波动正常，看 mAP |
| 标签错一个字段全盘错 | 我们目视抽验过字段含义（睁=0 闭=1） |
| 指标虚高但实际不能用 | 评估集是"陌生人"（跨受试者），更接近真机 |
| GPU 报 sm_120 不支持 | RTX 50 系必须 cu128+ 构建，别用默认 PyPI 的 torch |

### 7.2 词汇表

| 术语 | 英文 | 一句话解释 |
|---|---|---|
| 边界框 | bounding box / bbox | 框住目标的矩形，YOLO 标注为 cx cy w h（归一化） |
| 置信度 | confidence | 模型对"这有个目标且是某类"的确信度 0~1 |
| 真值 | ground truth (GT) | 人工标注的正确答案（我们的文件名标签） |
| 轮次 | epoch | 全部训练数据过一遍 |
| 批次 | batch | 一次前向/反向传播用的图片数 |
| 前向/反向传播 | forward/backward pass | 算预测 / 算梯度 |
| 学习率 | learning rate (lr) | 每次改权重的步长，0.01 是常用起点 |
| 预热 | warmup | 训练开头用小 lr 热身几轮，保护预训练权重 |
| 过拟合 | overfitting | 训练集越来越好、验证集开始变差 = 开始背题 |
| 早停 | early stopping | 验证指标连续 N 轮不涨就停，防过拟合也省时间 |
| 交并比 | IoU | 两框交集/并集，衡量框画得准不准 |
| 精确率/召回率 | precision / recall | 报得准不准 / 抓得全不全 |
| 平均精度 | AP / mAP | PR 曲线下面积（对类别取平均 = m）AP |
| 迁移学习 | transfer learning | 拿别人的预训练权重当起点 |
| 数据增强 | augmentation | 随机变换图片，免费扩数据 |
| 非极大值抑制 | NMS | 去掉同一目标的重叠框（YOLO26 已内置免除） |
| 显存 | VRAM | 显卡内存，batch 大小的主要约束 |

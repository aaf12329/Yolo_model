## 1. 仓库里现在有几个模型，分别是什么

| 文件（models/） | 类别 | 训练数据 | 准确率（跨受试者 val） | 用途 |
|---|---|---|---|---|
| `eye_yolo26n.pt` | 2 类：open_eye / closed_eye | MRL 84,898 张眼部特写 | **94.33%** | 眨眼确认、闭眼过久安全停止 |
| `gaze_yolo26s.pt` | 3 类：look_up / center / down | Columbia 眼部裁剪 11,760 张 | **95.62%** | **前进/停/后退 主控模型** |
| `gaze5_yolo26s.pt` | 5 类：上/中/下/左/右 | 同上 + 水平方向重标注 + 翻转互换增强 | **80.90%** | 扩展：左右转向（演示/探索版） |
| `face_landmarker.task` | 不是我们的模型 | Google MediaPipe 官方 | — | 定位人脸 478 点 → 裁眼（三个模型都吃它的输出） |

**分工建议**：轮椅前进/后退控制用 `gaze_yolo26s.pt`（3 类，最可靠）；
要看左右就上 `gaze5_yolo26s.pt`（left/right 达到 85~87%，但 center 弱）。

## 2. 原理：一张眼部小图是怎么变成"前进/后退"的

```
摄像头帧（未镜像！镜像会翻转左右语义）
   │  MediaPipe face_landmarker.task：478 个人脸关键点
   ▼
定位左右眼 → 按固定扩边裁出两张眼部小图（水平×1.6、垂直×2.2，含眉毛上下文）
   │  每张小图独立送入 YOLO26（imgsz=128）
   ▼
YOLO26 输出：这张图里"眼睛区域"属于哪个类 + 置信度
   │  双眼合并：一致取一致，不一致取置信度高者
   ▼
状态机（时间维度）：同一方向连续稳定 0.7s 才生效 ←—— 这一步把"逐帧分类"变成"追踪"
   ▼
动作映射：look_up→FORWARD  look_center→STOP  look_down→BACKWARD
          look_left→TURN_LEFT  look_right→TURN_RIGHT
```

为什么"训练用图片、使用靠视频"不矛盾：视频就是连续的单帧。模型每帧判一次
（GPU 0.5~2.4ms，远低于 33ms/帧的实时预算），"追踪"的感觉来自状态机的时间平滑。

**为什么用"整图单框"训练**：数据集的每张图就是一个眼部特写（或裁剪），YOLO 标注
`类别 0.5 0.5 1.0 1.0`（框住全图）。模型实际学的是"这种画面属于哪个类"——
对裁剪输入等价于分类，但保留了 YOLO 的部署便利（同一套管线）。

## 3. 逐张图解读 / What each figure shows

### 3.1 `runs/eye_yolo26n/curves_loss.png`（模型 A 损失曲线）

- **看什么**：四条线（train 的 box/cls 损失 + val 的 box/cls 损失）随轮次下降。
- **说明了什么**：train 损失一路下降=模型在学会训练集；val 损失大体跟降=没有
  死记硬背（过拟合）。val cls 损失在第 5/13/16 轮的尖峰是**小验证集的正常波动**
  （只有 3 个人、2,487 张，个别难者的图阶段性拉高），不是问题。
- **怎么下结论**：这条图不能单独下结论，配合 `curves_metrics.png` 的 mAP 看。

### 3.2 `runs/eye_yolo26n/curves_metrics.png`（模型 A 指标曲线）

- **看什么**：precision / recall / mAP50 / mAP50-95 四条验证指标随轮次。
- **说明了什么**：mAP50 在第 5 轮后就稳定在 0.95+，说明**任务很快收敛**；
  曲线平台期=继续训练收益枯竭，这正是早停（第 22 轮停、取第 13 轮 best.pt）的依据。

### 3.3 `docs/comparison/mrl_eye_confusion_matrix.png`（模型 A 混淆矩阵）

- **怎么读混淆矩阵**：行=真值，列=预测。**对角线=判对的数量**（越深越好），
  非对角=错误。左上+右下深、右上+左下浅 = 好。
- **图里的数字**：闭眼 1728/1800 判对（96.05%），睁眼 616/687 判对（89.80%）。
- **它说明什么**：睁眼的 71 个错误主要来自 MRL 标签噪声（部分"睁眼"图其实是
  垂目/眯眼）——所以准确率是下限。

### 3.4 `docs/comparison/columbia_gaze_confusion_matrix.png`（模型 B 3 类）

- **图里的数字**：look_center 96.29% / look_down 98.57% / look_up 92.00%。
- **它说明什么**：**down→up 为 0 例**——前进/后退两个反向指令绝不互窜；
  误差集中在 up→center（28 例），语义是"该前进时没动"，属安全侧错误。

### 3.5 `docs/comparison/columbia_gaze5_confusion_matrix.png`（模型 B 5 类）

- **图里的数字**：left 87.4% / down 83.2% / up 84.1% / right 80.2% / **center 42.1%**。
- **它说明什么（重点）**：
  1. **center 弱是结构性的**：注视空间里 上/下/左/右 是"一片区域"，而 center 是
     "一个点"（V=0 且 H=0），视线稍有偏差就出类。且对角视线（斜上左等）被单标签
     强行归类，天然含糊。
  2. 上/下 与 左/右 之间出现斜向互窜（up→left 49、down→right 28）——对角样本
     归类边界模糊的直接后果。
  3. **对控制的意义**：up/down/left/right 互相之间没有直接互窜到"反向"的情况
     （up→down 0、left→right 3），错误大多是"掉回 center"或"偏到相邻斜向"，
     状态机可兜底；center 误报由 0.7s 持续注视确认过滤。
- **结论**：5 类版适合做左右扩展的演示；**主控仍用 3 类版**，等个人化数据把
  center 补足（自采时 center 段可以多录）再切换。

### 3.6 `docs/comparison/*_accuracy_chart.png`（三张柱状图）

- **看什么**：各类准确率柱状图 + 最右侧 MediaPipe 检出率柱（全是 0%）。
- **说明了什么**：同场景下 MediaPipe 的 EAR 法结构性失效（需要整脸），YOLO26
  在眼部裁剪上 80~96% —— 这就是"为什么要换模型"的一图流答案。

### 3.7 `docs/training/summary.md` / `summary_gaze.md`

- 每次训练的文字档案：数据构成、划分方式、超参数、最终指标、产物路径——

## 4. 数字之间的换算关系（拿模型 A 举例）

```
混淆矩阵（行=真值，列=预测）          真值闭眼 1800 张，真值睁眼 687 张
                    预测闭眼   预测睁眼
真值闭眼(TP/FN)       1728        71
真值睁眼(FP/TN)         70       616

accuracy  = (1728+616) / 2485            = 94.33%  ← 判对比例（部署视角）
precision = 1728 / (1728+70)             = 96.1%   ← 说"闭眼"时有多准
recall    = 1728 / 1800                  = 96.0%   ← 真闭眼抓住了多少
mAP50     = PR 曲线下面积（置信度阈值从 0 扫到 1 的综合能力）= 0.9718
```

## 5. 已知问题与下一步 / Known issues & next

| 问题 | 原因 | 对策 |
|---|---|---|
| 5 类版 center 只有 42% | center 在注视空间是一个点；Columbia 每方向组合样本少 | 自采数据 center 段多录；或改两阶段（先 3 类，center 时再判左右） |
| 5 类对角互窜 | 斜向 gaze 归属天然模糊 | 同上；或引入回归式 gaze 角度输出（后续方向） |
| 模型 A 对"睁眼但垂目"偶判 closed | MRL 闭眼类混有垂目样本（域差异） | 个人化微调；快照实测已记录在案 |
| 上/下/左/右互相基本不窜 | —— | 已验证的安全属性，保持 |

→ 在 `gaze_yolo26s.pt`（3 类）/`gaze5_yolo26s.pt`（5 类）底座上微调 →
`docs/integration.md` 接入状态机。

# 注视方向数据采集指南 / Gaze Data Collection Guide

> 本指南面向**采集人（你自己）**，说明为什么要录、怎么录、录到什么程度算合格。
> 命令速查见 [COMMANDS.md](../COMMANDS.md) 第 9 节；本文件是详细版。
> 目标产物：供阶段 6"注视方向模型（上看/中看/下看 → 前进/停/后退）"训练用的自制视频。

---

## 1. 为什么要自己录 / Why self-recorded data

- 公开数据集里**没有**"注视方向 + 检测框"的现成标注（MPIIGaze 只有视线向量、无框；
  Roboflow 需要注册且定义参差）。
- 更重要的原因：方向模型必须贴合**你本人**——脸型、眼镜反光、摄像头角度、
  使用环境的光照。别人脸的数据训出来的模型，装到你的轮椅上大概率不好使。
- 你只需要**录视频**，不需要画任何标注框：后续用 MediaPipe 虹膜位置自动打标
  （脚本我来写），视频 + 时间段 json 就是全部输入。

## 2. 采集前的准备 / Preparation

| 项 / Item | 要求 / Requirement | 原因 / Reason |
|---|---|---|
| 位置 | 坐在**实际使用轮椅时的位置**（原型阶段就是平时坐的桌前位置） | 训练分布 = 使用分布，模型才准 |
| 距离 | 和平时用摄像头视频通话的距离一致（一般 50~80 cm） | 太远眼睛像素太少，太近变形 |
| 眼镜 | 平时戴就**全程戴着**录 | 眼镜反光是最主要的干扰源之一 |
| 光照 | 用实际使用时的灯光；**不要背对窗户**（逆光） | 逆光时虹膜几乎不可见 |
| 摄像头 | 关掉其他占用摄像头的程序（EyeWheelchairProject 的 demo、QQ/微信视频等） | 摄像头是独占资源 |
| 状态 | 正常精神状态即可，不用刻意瞪眼或睁大 | 训练数据要和真实使用一致 |

## 3. 录制步骤 / Step by step

```bash
conda activate yolo
cd C:\Users\Guards\Desktop\yolo_model
python scripts/collect_gaze_video.py
```

1. 弹出预览窗口，顶部灰条显示 `SPACE=start q=quit (REC standby)` —— **先别动**，
   利用这个时间调整坐姿、确认头在画面里位置合适。
2. 按**空格**开始。顶部出现**彩色横幅**提示当前方向 + 倒计时：

   ```
   第 1 轮：往上看(20s) → 看中间(20s) → 往下看(20s)
   第 2 轮：往上看(20s) → 看中间(20s) → 往下看(20s)
   ```

3. 横幅切到"往上看"时，**眼球**向上转到舒适的最大幅度并保持到倒计时结束；
   "看中间"时直视摄像头；"往下看"时眼球向下。
4. 2 轮录满（约 2 分钟）脚本自动结束；中途想停按 **q**（已录部分有效）。
5. 结束时控制台会打印输出路径和分段数量（应有 6 段，正常结束）。

可选参数 / options:

```bash
python scripts/collect_gaze_video.py --seconds 15 --rounds 3   # 每段15秒、3轮
python scripts/collect_gaze_video.py --camera 1                # 换摄像头（外接USB时常用）
```

## 4. 硬性要求（唯一一条）/ The critical rule

### 🔴 头保持不动，只动眼球

- 上/下看时**不要抬头、不要低头、不要点头**，下巴当钉在原地。
- 原因：摄像头视角下"头低下去"和"眼球往下转"的图像特征很像，
  但轮椅上你不可能靠低头开车。头动了，模型学到的是**头部姿态**——
  在桌前指标很好看，装到轮椅上直接失效，而且这种错误**从指标上很难发现**。
- 自检方法：录完回放视频，用手指抵住下巴试试——手指不离开脸就能重演全程，才算合格。

其他要求（软性）：

- **眨眼自然**：不用憋着不眨，也不用刻意多眨；每个 zone 20 秒里自然眨十几次完全没关系。
- **幅度自然**：眼球转到舒适最大幅度即可，不要极限翻白眼，也不要斜视。
- **表情放松**：不要皱眉、咧嘴等夸张表情（会被误学成特征）。

## 5. 建议的采集计划 / Recommended plan

| 场次 | 条件 | 目的 |
|---|---|---|
| 第 1 场（必录） | 当前环境，默认参数（2 轮 × 20s × 3 方向） | 基础数据 |
| 第 2 场（强烈建议） | **换一种光照**（如晚上关灯开台灯 / 拉窗帘） | 光照鲁棒性 |
| 第 3 场（可选） | 换一件上衣/背景稍乱的桌面 | 减少背景依赖 |
| 第 4 场（可选） | 不戴眼镜（若实际使用中可能摘镜） | 覆盖两种状态 |

- 每场之间**隔几分钟**或换条件后再录，避免连续录时坐姿漂移被当成"方向特征"。
- 总量 2~4 场足够启动第一版方向模型；打标时会从视频里抽帧（每秒数帧），
  2 分钟视频 ≈ 数百帧样本，够用。
- 有条件的话**隔一天再补录一轮**：人困/精神时的眼睑位置不同，多天数据明显更稳。

## 6. 输出文件说明 / Output files

录完生成两个文件，位于 `C:\Users\Guards\Desktop\EyeWheelchairProject\data\raw_videos\`
（不进 git，属于 EyeWheelchairProject 的 data 目录）：

```
gaze_capture_20260928_193000.mp4   原始视频（mp4v 编码，30fps，摄像头原生分辨率）
gaze_capture_20260928_193000.json  分段信息，内容形如：
[
  { "zone": "up",     "t_start": 0.0,  "t_end": 20.0 },
  { "zone": "center", "t_start": 20.0, "t_end": 40.0 },
  { "zone": "down",   "t_start": 40.0, "t_end": 60.0 },
  ...（第 2 轮同理）
]
```

- `zone` 取值：`up` / `center` / `down`；`t_start`/`t_end` 是相对视频开头的**秒**。
- 这两个文件**同名成对**，后续自动打标脚本按文件名配对使用，**别改名、别分开存放**。

## 7. 录完后的自检清单 / Quality checklist

- [ ] 视频能正常播放（推荐 VLC/PotPlayer，mp4v 编码 Windows 自带播放器有时不支持）
- [ ] 回放时自己的脸全程在画面内，没有大半张脸出框
- [ ] 每一段里眼球确实朝提示方向看（而不是靠转头）
- [ ] json 的段数 = 轮数 × 3（默认 6 段），没有只录一半的段
- [ ] 光照下虹膜清晰可见（回放暂停看一下"看中间"的画面）

## 8. 常见问题 / Troubleshooting

| 现象 | 处理 |
|---|---|
| `cannot open camera 0` | 关掉占用摄像头的软件；外接摄像头试 `--camera 1` |
| 预览窗口卡住不刷新 | 按 q 退出重开；Windows 下首次开摄像头偶尔要几秒 |
| 结束后找不到文件 | 看脚本开头打印的 `输出 / output:` 路径（在 EyeWheelchairProject 里） |
| 视频打不开 | 用 VLC/PotPlayer；或重录（编码问题不影响打标，能用 VLC 播即可） |
| 录到一半想重来 | 直接重录一场即可，旧文件不冲突（文件名含时间戳），多余的删掉就行 |

## 9. 隐私说明 / Privacy
